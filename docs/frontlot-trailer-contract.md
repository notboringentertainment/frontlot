# What trailer approval means

Every trailer stage needs a signed approval through Frontlot's signing machinery. The approval belongs to the saved material being reviewed. A rough-cut approval belongs to one saved edit. Final approval belongs to that edit and the exact exported file. A newer stage approval replaces the earlier approval; restoring earlier files does not restore their approval.

A signature proves that the approval passed through the signing machinery and that its signed contents have not changed. It does not prove who was at the keyboard. A program running as Ben outside the assistant's sandbox can read the signing key and use the same machinery. This is a boundary for the embedded assistant's permitted work, not a separate operating-system account or protection against every program running as Ben. This piece does not change that trust model.

The embedded trailer assistant cannot read the signing key or write approval history. It cannot use Higgsfield, other external connectors, Chrome, web tools or direct shell network access. Paid work must use Frontlot's own operations, spending confirmation, receipts and spending total. Only Frontlot's own operations tool is loaded. Tool servers installed in Ben's personal account are excluded when a trailer starts or resumes. Local reading, writing in its work area and the sandboxed shell remain available; other built-in tools follow the permission rules. The startup self-check requires an actual call to Frontlot's tool as well as the sandbox checks. It checks tool availability before the operations connection starts, so an unavailable-connection reply is expected there. Separate local tests verify that the operations connection still runs a free operation. No paid operation runs during that check. Older productions keep their existing tools and instructions.

Starting and signing whole trailer stages through buttons are later pieces. An unsigned draft is visible, but no stage can begin. The generic version-change request cannot establish that a draft was created as a trailer: editable project fields are not proof. A later trusted creation control must establish the initial signed trailer record as part of Ben's creation action. After that record exists, a trailer cannot change to an ordinary production definition.

If a caller supplies another pipeline name for an already signed trailer, the existing reader and writer continue enforcing the signed trailer definition. That safe override is retained here rather than changing the older calling convention.
