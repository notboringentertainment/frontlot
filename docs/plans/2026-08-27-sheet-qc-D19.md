# Plan D19: Sheet QC — machine-checked acceptance before a human is asked
_Drafted by Claude for Codex review, 2026-08-27. Follows the claudex-loop Phase 2 protocol; MAX_ROUNDS=5. Revision 2 after Codex round 1 (20 findings; 19 accepted, 1 narrowed — see REVIEW-LOG)._

## Goal
Stop presenting defective character sheets to the human. On the Bloodless pilot (2026-08-26) the operator presented, in sequence, a turnaround with a cigarette in two portraits (a conditional prop rendered from the look spec), a turnaround with the shoes cropped, and a turnaround whose two "profiles" both faced left. Each was caught by Ben, not by the pipeline; each cost a round trip and $0.135. The director skill now carries an acceptance checklist (`skills/pipelines/authored-film/visual-bible-director.md`, "Sheet acceptance checklist"), but a checklist an agent reads is advice. D19 makes it a gate precondition: every sheet asset must carry a passing, receipted QC verdict from an independent vision judge before a `sheet` gate request can be constructed, and the generation loop regenerates on its own (bounded) before the human sees anything.

Out of scope: judging artistic quality or likeness as pass/fail (the human still approves identity); locations and posters (same mechanism later, separate checklists); replacing the human gate; automatic prompt repair.

## Threat model, stated honestly (R1#1)
Same boundary as `lib/gates.py:26`: process discipline, not OS privilege. QC guards against **operator and model error** (the failure that actually happened) and against **pipeline code that follows its contract** skipping or replaying a check. It does not resist a hostile local process holding the user's account; such a process can already read the HMAC key. The human gate remains the only canon authority; QC narrows what reaches it. Every "cannot" below means "has no API path within the contract, and any bypass is detectable as an unsigned/unledgered/mismatched receipt".

## Diagnosis (verified 2026-08-27)
- Sheet views come from `SeedreamImage.execute` through `paid_call_context` with a builder-1.3 `prompt_recipe` and a generation receipt per asset. Nothing between generation and the gate inspects pixels.
- `scripts/gate_approve.py::_construct_character` verifies only project-local path + bytes (`_verify_image_ref`, line 227) and signs `character_approval_record`; it does **not** rerun lineage / recipe / active-look / active-headshot checks (R1#11). Canon enforcement does those at checkpoint write only.
- `paid_call_context` (`tools/video/_shared.py:983`) always runs visual look governance and expects a generation-shaped receipt with media `output_sha256` and a WAL `output_path` (R1#3, #4). Generation receipts have no one-use token (R1#4). Canon enforcement indexes generation receipts by `output_sha256` (`canon_enforcement.py:1769`) (R1#5).
- `project_config.schema.json` is `additionalProperties: false`; `provider_egress.provider` enum is FAL-only; Bloodless's signed config authorizes FAL only (R1#2). Authored-film 1.2's authoritative `tools_available` lists no judge; the manifest is digest-pinned (R1#18).
- `CostTracker._save` rewrites `cost_log.json` without an interprocess lock (R1#15). `resume_check` blocks on any non-terminal reservation (R1#14).
- `tools/prompt_builder.py` `wardrobe` template hardcodes a Bloodless-specific variant; `BUILDER_VERSION` is a hand-maintained string (R1#19). `sheet_roles()` admits legacy single-angle roles with no checklist (R1#20).
- Keys in `.env`: `OPENAI_API_KEY`, `GOOGLE_API_KEY`; no Anthropic key.

## Design

### D19.0 Pipeline version and config version (R1#2, #18, #20)
- **authored-film 1.3** manifest: identical to 1.2 except `visual_bible.tools_available` adds `sheet_judge`, and the stage contract states "every sheet ImageRef requires a current QC pass receipt; legacy roles (`front`, `three_quarter`, `profile`, `full_body`) are not permitted in a 1.3 sheet". Bloodless adopts it through a signed `pipeline_migration` receipt (`scripts/gate_approve.py` kind `pipeline_migration`, existing). QC enforcement is keyed on the pin (`_is_qc_manifest(pin)`), so 1.1/1.2 projects are untouched.
- **project_config 1.1**: adds `qc: {judge_provider: enum[openai, google], judge_model: string, policy_version: string}` and lets `provider_egress` be a **list** of `{provider, content_classes[]}` with `provider` enum `[fal, openai, google]` and a new content class `generated_sheet_images` (synthetic outputs + the imported_synthetic hero only; `casting_inspiration` is never an egress class anywhere). Bloodless re-signs its config (`config` receipt + `approval_policy` decision line, existing mechanism). **No provider fallback at runtime**: a verdict is accepted only if its `provider`/`model`/`policy_version` equal the signed config (R1#9). Changing provider = new config receipt.

### D19.1 Checklists are versioned policy, hashed (R1#13, #20)
`lib/sheet_qc/policy.py`: `QC_POLICY_VERSION = "1.0"`; per role (`turnaround`, `expressions`, `wardrobe` — the only roles a 1.3 sheet may carry) an ordered list of items `{id, question (YES = pass), severity: fail|warn, evidence: none|wardrobe_pieces|hero_image}`. `policy_sha256 = record_sha256({version, role, items})`. Turnaround items (all `fail` unless marked):

| id | question |
|---|---|
| panels_7 | Exactly seven panels: four full-body over three portraits? |
| profiles_opposite | Do the two full-body profile panels face opposite directions (one nose to the left edge, one to the right)? |
| portraits_opposite | Do the two profile portraits face opposite directions? |
| shoes_visible | Are both shoes fully inside the frame on every full-body panel? |
| hands_empty | Are the hands empty in every panel, with nothing held and nothing at the mouth? |
| wardrobe_complete | Is every listed wardrobe piece visible where the angle allows? (evidence: wardrobe_pieces) |
| head_height | Same head height across the full-body row and same facial scale across the portraits? (warn) |
| one_light | One consistent light direction across all panels? (warn) |
| single_subject | Exactly one person, the same person, in every panel? |
| no_text | No text, watermark or logo? |

Expressions: `grid_2x3`, `head_shoulders_only`, `realism_matches_hero` (evidence: hero_image; warn), `mouth_clear`, `no_hands_props`, `six_distinct` (warn), `single_subject`, `no_text`. Wardrobe: `variants_side_by_side`, `full_body`, `pieces_visible` (evidence: wardrobe_pieces), `single_subject`, `no_text`.

**Verdict computation is code, not model** (R1#13): the judge's answers are normalised into a map over the authoritative item ids; any missing, duplicate or unknown id → `fail` with reason `coverage`; `unsure` → `no`; any `fail`-severity `no` → `fail`; `warn` items populate `warnings[]` and never block (Q1 resolved: printed at the gate, never blocking).

**Deterministic pre-checks** (R1's "smaller design", narrowed): before any paid call, `lib/sheet_qc/local_checks.py` rejects what needs no model — file is a regular file (not a symlink), decodes as PNG, dimensions match the role's expected size/aspect (turnaround 2560×1600 ±2%; expressions 3:2 grid within tolerance), no alpha, single image. Panel counting and crop detection by pixel heuristics are **not** attempted (a plain-background sheet defeats naive segmentation and a wrong deterministic answer is worse than a model's `unsure`); they stay with the judge. Local failures produce a `fail` verdict receipt too (provider `local`), so they count as attempts.

### D19.2 The judge: its own paid-inference context and its own receipt stream (R1#3, #4, #5, #7, #17)
`tools/qa/sheet_judge.py` (`SheetJudge(BaseTool)`) with provider adapters `openai` (Responses API, image input, `text.format: json_schema`, temperature 0, `max_output_tokens ≤ 600`) and, **only if the signed config names it**, `google`. Input: `{project_dir, entity_id, role, asset_id}`. No caller-supplied prompt, path, look, or hero: everything is resolved from signed state.

Execution, in order:
1. **`qc_call_context(project_root, ...)`** — new in `tools/video/_shared.py`, sibling of `paid_call_context`: config receipt + `approval_policy` binding, pinned-manifest ≥1.3 check, egress consent for `generated_sheet_images` to the configured provider, `resume_check`, per-call budget reservation, WAL entry whose durable output is the **canonical verdict JSON** (not a media file), reconciliation on indeterminate outcomes. It does **not** run look/prompt-recipe governance (there is no generation prompt); it verifies the evaluated asset instead (step 2).
2. **Bytes, not paths** (R1#7): open `canon/visual/objects/<asset_id>.png` with `O_NOFOLLOW`, require a regular file, read once into memory, hash the buffer, require it to equal `asset_id`; the same buffer is what gets base64-encoded to the provider. The hero for `realism_matches_hero` is resolved the same way from the **active headshot receipt** (`lib.headshots.active_headshots`), never from a path.
3. Judge prompt = fixed system prompt (in-repo, hashed into `prompt_sha256`) + policy items + evidence fields from the **signed active look** (`default_wardrobe.pieces`, `hair`, `age_band`) + the image(s). The model returns `{items:[{id, answer: yes|no|unsure, note ≤ 20 words}]}` under a JSON schema.
4. **Idempotency** (R1#17): a persisted idempotency key `sha256(project, entity, role, asset_id, policy_sha256, look_hash, hero_asset_id, provider, model)` is written to the WAL before the request; on transport timeout after send, the provider request id (if any) is attached and the call goes to `reconcile`, never resubmitted blindly.
5. **One verdict per evaluation tuple** (R1#8): under the QC stream lock, if a verdict already exists for the tuple in step 4, the tool returns it and makes no call. A pixel-identical asset therefore has exactly one verdict per policy version. Re-judging requires a new `policy_version` (new tuple) or a human `qc_override` (D19.4). There is no "newest wins".
6. **QC receipt** (`lib/qc_receipts.py`, modelled on generation receipts but a separate module): file `qc-receipts.jsonl` (project), global ledger `qc-ledger.jsonl`, chain stream `chains/<sha(project)>.qc.jsonl` + tip, WAL `qc-wal`. Signed record binds (R1#6): `project_id, entity_kind, entity_id, role, asset_id, look_hash, look_receipt_id, headshot_asset_id, headshot_receipt_id (null unless evidence hero_image), policy_version, policy_sha256, provider, model, prompt_sha256, response_sha256, verdict, items[], warnings[], cost_usd, idempotency_key`. `lib.canon_enforcement` never reads QC rows through the generation index; it calls `verified_qc_receipts(project_dir)` which is typed and separate (R1#5).

`--dry-run` / fake judge (R1#9): the fake provider exists only in `tests/` and is refused by `qc_call_context` unless `OPENMONTAGE_TEST_MODE` is set by the test harness **and** the project is under a tmp path outside `PROJECTS_DIR`; it can never write to a real project's streams. `require_qc_pass` additionally rejects any verdict whose `provider`/`model`/`policy_version` differ from the signed config, so a fake row is inert even if it existed.

### D19.3 The gate and canon enforcement share one verifier (R1#6, #11, #12)
- `lib/sheet_qc/verify.py::require_qc_pass(project_dir, entry, *, config, pin)`: for every role in `sheet_roles(entry)` (1.3: must be ⊆ {turnaround, expressions, wardrobe}), take the entry's declared `qc_receipts[role]` id (D19.3b), load it from `verified_qc_receipts`, and require: signature/ledger/chain valid; `asset_id` == the ImageRef's; `role` matches; `look_hash`/`look_receipt_id` == active look; for hero-evidence items `headshot_asset_id` == active headshot; `policy_version`/`policy_sha256`/`provider`/`model` == signed config; `verdict == pass` **or** a valid `qc_override` receipt (D19.4) covers every failing item. Anything else → `QCRequired(role, reasons)`.
- **3b. QC ids live in the signed record** (R1#12): visual_bible 1.1 character entries gain an optional `qc_receipts: {role: receipt_id}` (schema: optional property; required by enforcement under pin ≥1.3). `character_approval_record` includes `qc_receipts` when present, so the human-signed digest covers exactly which verdicts were relied on; any change between display and signing changes the digest and the gate refuses.
- **One shared sheet verifier** (R1#11): extract `lib/sheet_verify.py::verify_character_sheet(project_dir, entry, *, pin)` from `canon_enforcement` (lineage, generation receipt, recipe/look binding, active headshot, and now QC) and call it from three places: checkpoint write (existing path), `gate_approve._construct_character` (new), and the gate's pre-commit re-check inside the receipt transaction (new). The gate can no longer sign an entry that canon enforcement would later reject.

### D19.4 Human override is its own receipt (R1#10)
`scripts/gate_approve.py` gains kind `qc_override`: request names `(qc_receipt_id, item_ids[])`; the handler reloads the QC receipt, shows the image, the item questions, the judge's notes, and asks for a typed reason; the signed record binds `{qc_receipt_id, asset_id, role, item_ids, reason}`. `require_qc_pass` accepts a failed verdict only when every failing `fail`-severity item is named by a valid override receipt for that exact `qc_receipt_id`. No override for a missing verdict (the judge must have run), and an override never satisfies a different asset or policy version. `qc_receipts` in the entry and the approval record therefore already cover overrides transitively (the override binds the QC receipt id).

### D19.5 One command makes a sheet, bounded and durable (R1#14, #15, #16)
`scripts/sheet_run.py --project <slug> --entity <id> [--roles turnaround,expressions] [--max-attempts 3] [--open]` replaces `scripts/bloodless_sheet_ace.py` (deleted). Project-agnostic: look, headshot, palette (from the proposal packet) all from signed state; invented names only in tests.
- **Workflow lock**: `lib.run_lease` style lock on `(project, entity)` held across resume-check, attempts, checkpoint write and gate-request write. A second runner refuses immediately with the holder's pid/time.
- **Affordability preflight, then per-call reservations** (R1#14): compute `max_attempts × (generation price + judge price)` for the remaining roles; refuse to start unless the project cap covers it; then each generation and each judge call reserves individually through its own context (no aggregate hold, so `resume_check` semantics are unchanged).
- **Cost persistence lock** (R1#15): `CostTracker._save` and the budget check run under an `fcntl` lock on `cost_log.json.lock` (small change, tested with two processes).
- **Durable attempts** (R1#16): `qc-attempts.jsonl` (project, append-only, not signed — it is a counter, not authority): `{entity, role, look_hash, policy_sha256, attempt_n, generation_receipt_id, qc_receipt_id, verdict, failing_items, cost_usd}`. On start, existing rows for the tuple count toward `max_attempts`; an existing `pass` for the tuple is reused without any paid call.
- Loop per role: generate (governed, unchanged inputs; the prompt is never mutated by the loop) → judge → on `fail`, print failing items and retry until the cap; then `blocked`, exit non-zero, nothing presented. All attempts' assets and receipts stay in the vault.
- On all roles passing: write `visual_bible` (`awaiting_human`, entry `status: draft`, next `sheet_revision`, `qc_receipts` filled), write the `sheet-<entity>-<n>` gate request, print the approval command; `--open` opens the passing images and the `by-entity` view is rebuilt.

### D19.6 Builder hygiene (R1#19)
- `wardrobe` template renders variants **from the look**: "left in the default outfit; right in the '<variant.name>' variant (<variant.when>)" for each `wardrobe_variants[]` entry; no project-specific words in `prompt_builder.py`. Variant garments come from the look or are not stated (the look spec gains an optional `wardrobe_variants[].pieces[0..8]` in look_spec 1.1 — a separate, small schema bump handled as: builder renders `pieces` when present, else name+when only).
- `BUILDER_VERSION` becomes derived: `builder_policy_sha256 = record_sha256({templates, negative defaults, rendering rules})`, recorded in `prompt_recipe` beside the human-readable version; any template edit changes the hash without anyone remembering to bump.

### D19.7 Skill
`visual-bible-director.md`: "run `scripts/sheet_run.py`; never hand-generate sheet views; present only what the run produced; the checklist in this file is what the judge enforces — read it to understand a failure, not to replace the judge."

## Key decisions & tradeoffs
- **Judge = external model; the operator's eyes are the second check, not the first.** The failures were perception failures. Risk of judge error is handled by `unsure→no`, warn tier for subjective items, and a recorded human override.
- **Separate QC stream, not the generation stream.** Different shape (verdict JSON, no media), different index (evaluation tuple, not `output_sha256`), and it keeps canon lineage checks untouched.
- **One verdict per tuple; no judge shopping.** Stochastic passes are not passes.
- **No runtime provider fallback.** Egress is human consent per provider; a fallback would be silent egress to a provider nobody approved.
- **Regeneration never edits the prompt.** Persistent failure is a builder bug and is fixed under a policy hash change, as happened three times on 2026-08-26.
- **Deterministic checks only where they are actually deterministic.** Codex suggested local panel-count/crop/OCR checks; accepted for file/format/dimension checks, declined for pixel heuristics (false confidence).

## Assumptions
1. OpenAI Responses API with the configured model accepts a 2560×1600 PNG plus a hero PNG as image inputs and honours JSON-schema output; per-call cost ≤ $0.05. — source: same key as `sora_video.py`; **verified by the step-4 probe before anything depends on it**; if it refuses photoreal faces, the human re-signs config for `google` (no silent fallback).
2. The judge answers geometric items (facing direction, cropped shoes, item in hand) reliably at temperature 0. — measured on the four real 2026-08-26 images as regression fixtures: `4b1b3a4f…` must fail `hands_empty`; `16dadc8c…` must fail `shoes_visible`; `d3e77a3b…` must fail `profiles_opposite`/`portraits_opposite`; `0b09fb34…` must pass.
3. `lib.run_lease` (existing) is reusable for the `(project, entity)` workflow lock. — to confirm in step 6.
4. Bloodless's $100 cap has room; judge cost per sheet ≈ $0.02–0.10.

## Risks / open questions
- R1: `wardrobe_complete` false negatives when a piece is hidden by the angle → wasted regenerations. Mitigation: "where the angle allows" phrasing; attempt cap; the override path.
- R2: Two-image input doubles tokens; if too costly, `realism_matches_hero` drops the hero image and stays warn-tier.
- R3: More streams (qc receipts, attempts) = more files an operator must not hand-edit; all are append-only and the signed ones are verified, the attempts file is a counter only.
- R4: Manifest 1.3 + config 1.1 means two more human signatures on Bloodless before the next sheet; acceptable and one-time.

## Out of scope
Location and poster QC; likeness as pass/fail; automatic prompt repair; changing who approves canon; resisting a hostile local process holding the user's account (documented boundary).
